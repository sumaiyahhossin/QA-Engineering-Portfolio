# Manual Test Execution Tracking

**Project:** Healthcare Plan Browsing and Public Account Access  
**Workbook:** `Humana_Manual_Test_Cases.xlsx`  
**Execution worksheet:** `Test_Execution`

---

## Execution Record

The Excel workbook is the working execution tracker for the 50 manual test cases. This Markdown page provides context for how results should be recorded; it does not replace the workbook or independently certify historical execution totals.

Before publishing aggregate pass/fail counts, confirm them against the original execution records.

| Status | When to use it |
| :--- | :--- |
| **Passed** | The test was executed and the actual result matched the expected result. |
| **Failed** | The test was executed and the actual result did not match the expected result. |
| **Blocked** | The test could not proceed because of an environment, access, or dependency issue. |
| **Skipped** | The test was intentionally not executed. |
| **Not Run** | No execution has been recorded. |

## What to Record

For each execution, record the following when the information is available:

- Test case ID.
- Execution date.
- Test environment or build reference, if appropriate to share.
- Actual result.
- Status.
- Defect reference, if one was created.
- Relevant notes or evidence location.

## Public Portfolio Notes

- Do not publish internal ticket IDs, private environment names, member information, screenshots, or logs from employer systems.
- Use generalized references in public examples.
- Only report pass rates and execution totals after checking the source workbook.
- A test case being documented does not mean it has been executed.
