Test Strategy

Project Name: Healthcare Plan Browsing and Member Coverage

Company: Humana

1. Testing Objectives

- Verify that application features meet documented requirements.
- Validate healthcare plan browsing and member coverage workflows.
- Identify defects before application releases.
- Confirm that resolved defects do not affect existing functionality.

2. Testing Levels

Functional Testing
Verify individual features and user workflows.

Integration Testing
Verify that connected application components exchange information correctly.

Regression Testing
Verify that application changes do not break existing functionality.

Smoke Testing
Verify that the major application functions work after a new build or deployment.

3. Testing Types

- Positive Testing
- Negative Testing
- Boundary Testing
- UI Testing
- Database Validation
- Cross-Browser Testing

4. Manual Testing Strategy

- Review requirements.
- Identify test scenarios.
- Prepare test cases with expected results.
- Execute test cases.
- Record actual results.
- Report and retest defects.

5. Automation Testing Strategy

Automation focuses on repeatable and important workflows using Java, Selenium WebDriver, and TestNG.

Automated testing activities include:

- Browser initialization.
- Application navigation.
- Form and field validation.
- Workflow verification.
- Assertion-based result validation.
- Automated test execution and reporting.

6. Defect Management Strategy

Defects are documented and tracked using Jira. Each defect includes:

- Summary
- Description
- Steps to reproduce
- Expected result
- Actual result
- Severity
- Priority
- Evidence

7. Test Data Strategy

Test data should cover valid, invalid, missing, and boundary-value scenarios. Sensitive member information must not be included in public portfolio examples.

8. Tools and Technologies

- Java
- Selenium WebDriver
- TestNG
- Maven
- Jira
- Zephyr
- Oracle SQL Developer

9. Regression Strategy

Regression testing is performed after application changes, defect fixes, and updates to important healthcare workflows.

10. Reporting

Testing results are documented with execution status, defects identified, retest results, and outstanding issues.
