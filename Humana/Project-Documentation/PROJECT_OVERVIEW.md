# Healthcare Plan Browsing & Member Portal QA

**Company:** Humana  
**Role:** Junior QA Analyst  
**Dates:** October 2023 – March 2025  
**Methodology:** Agile / Scrum

## Project Overview

I worked on testing healthcare application workflows for browsing health plans and viewing plan and member information. The main areas I tested included ZIP code search, plan listings, plan details, sign-in, and related form behavior.

My QA work included manual test design and execution, browser automation with Java and Selenium WebDriver, defect tracking, and SQL checks when database validation was needed.

## My Responsibilities

- Reviewed requirements and discussed questions with developers and product owners.
- Created and updated manual test cases.
- Ran functional, smoke, regression, and integration tests.
- Checked ZIP code searches and plan search results.
- Reviewed plan details and coverage information.
- Tested sign-in behavior and required-field validation.
- Wrote Selenium WebDriver tests in Java for selected workflows.
- Used TestNG for test setup, assertions, and suite execution.
- Used SQL to check test records and related data when access was available.
- Reported and followed up on defects in Jira.
- Maintained test cases in Zephyr.
- Participated in Agile ceremonies and team discussions.

## Main Testing Areas

### Plan Search
- Entered ZIP codes and checked field validation.
- Submitted searches and reviewed the results.
- Checked plan names and displayed information.

### Plan Details and Coverage
- Opened plan details from search results.
- Checked the information displayed on plan pages.
- Reviewed member coverage scenarios and related date or status information.

### Sign-In and Forms
- Checked sign-in page behavior.
- Tested valid-format and invalid inputs.
- Checked required fields and validation messages.

### Data Checks
- Used SQL queries to review test records, dates, statuses, and relationships between related records when database access was available.

The folders alongside this document contain the manual test cases, project notes, Selenium code, and SQL examples related to these testing areas. The public Selenium suite uses local HTML pages and synthetic values so the browser tests can be run independently from this repository.
